Python code style

This page renders the reference file that all PaperLoop subagents follow. The Markdown source is in .refs/python-code-styles.md.

Python Code Styles

  • Use Google Python Style as code style reference with the following exceptions.
    • Enforce a line break at the end of each complete docstring sentence.
    • Follow the custom line length rules.
    • Follow the custom indentation rules.
  • Use ASD-STE-100 non-strict mode with academic US English fallback as natural language style reference.
  • Use a maximum line length limit of 119 characters.
    • Use "smart" line breaks to improve sentence and code readability.
    • Do not use "dumb" line breaks that affects sentence or code readability just to satisfy the rules.
  • Use 4-space indentation.
    • Use horizontally aligned hanging indents.
    • Do not use vertically aligned indents.
  • Use complete and meaningful words to name things instead of short and confusing mathematical notations.
    • Long and clear names are better than single character names that makes no sense.
    • Do not use overly abbreviated names.
  • Use from ... import ... and from ... import ... as ... wherever possible.
  • Use ruff to organize imports.
